# Проверка интерфейса LogParser

Это инструкция ручной проверки, а не отчёт о пройденных тестах.
Заполнить результаты после запуска на указанном коммите.

- Дата: не заполнена.
- Коммит (`git rev-parse HEAD`): не заполнен.
- ОС и терминал: не заполнены.
- Исполнитель: не заполнен.

## Подготовка

Запустить из корня репозитория на демонстрационной базе:

```sh
docker compose up -d --wait db
docker compose build logparser
docker compose run --rm logparser import samples/sample.log samples/app.log
docker compose run --rm -it logparser view
```

Команды не очищают существующие данные. Если в базе уже есть другие журналы,
количество записей может отличаться. Для точного сравнения использовать
отдельную тестовую базу только с этими двумя файлами. Не очищать рабочую базу
ради проверки. Повторный импорт примеров не должен добавлять дубликаты событий.

## Сценарии

Команды вводятся внутри `view`, после каждой нажать Enter.
Номер записи относится к текущей странице.

| № | Действие | Ожидаемый результат | Факт |
|---|---|---|---|
| 1 | Открыть view | Журнал, номер страницы, подсказки и сообщение о лимите 100 записей | Не проверено |
| 2 | n, затем p | Следующая и предыдущая страницы; на первой странице p не меняет страницу | Не проверено |
| 3 | /inventory | В примере найдена запись Inventory service unavailable | Не проверено |
| 4 | 1 после поиска | Операция f7a8b9: три события со смещениями 0; 0,500; 9,800 с. Подпись о лимите журнала отсутствует | Не проверено |
| 5 | b | Возврат к журналу; поиск inventory и исходная страница сохранены | Не проверено |
| 6 | e, затем e при активном поиске | Переключение ошибок/всех уровней; текст поиска сохраняется | Не проверено |
| 7 | / | Сброс только текстового поиска; фильтр уровня не меняется | Не проверено |
| 8 | /несуществующая_метка_1839 | Сообщение «Записей не найдено», страница 1/1; n и p не выводят за границы | Не проверено |
| 9 | ./inventory | Подсказка о неверной команде; правильная команда начинается с / без точки | Не проверено |
| 10 | Сбросить поиск и выбрать запись без trace_id | Сообщение об отсутствии trace_id; просмотр продолжается | Не проверено |
| 11 | Выбрать номер отсутствующей строки на неполной странице | Сообщение «Такой строки нет» | Не проверено |
| 12 | q | Завершение просмотра; после выхода echo $? показывает 0 | Не проверено |

## Ограничение журнала

`view` получает не более 100 последних записей, подходящих под текущие фильтры,
и разбивает результат на страницы по 8 строк. Число «Записей» относится к этой
выборке, а не ко всей базе. Поиск выполняется запросом к базе: фильтр применяется
до ограничения количества строк.

Для проверки границы нужны более 100 подходящих событий: ожидаются 100 записей,
13 страниц, четыре строки на последней странице. Команда n на последней
странице не должна менять страницу. Эта проверка пока не выполнена.

При открытии операции используется отдельный запрос по trace_id. Лимит
журнала не переносится на цепочку операции. Для большей выборки в CLI:

```sh
docker compose run --rm logparser search -n 500
```
