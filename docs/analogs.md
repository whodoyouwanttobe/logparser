# Аналоги и что мы из них взяли

| Инструмент | Что это | Полезные идеи | Что взяли в logparser |
|---|---|---|---|
| **lnav** (Log File Navigator) | консольный просмотрщик логов: сам распознаёт формат, подсвечивает уровни, умеет SQL-запросы к логам | цвет по уровню, фильтры по времени и уровню, SQL поверх логов | цвет по уровню в `ui.c`, фильтры `-l/-s/-u`, хранение в PostgreSQL, по которому можно писать любые SQL-запросы |
| **journalctl** (systemd) | просмотр системного журнала | `--since 1h`, `-p err` (уровень не ниже), `-u` (по сервису), вывод в разных форматах | относительное время `-s 1h`, `-l error` («не ниже»), `-p` (программа), CSV; импорт из `journalctl -o short-iso` |
| **GoAccess** | консольный анализатор веб-логов со сводной статистикой | топ-N, гистограмма по часам прямо в терминале | `stats`: топ-N программ, хостов и операций, активность по часам |
| **Grafana Loki / Graylog / ELK** | серверные системы: агенты собирают логи, а отдельный интерфейс их анализирует | поиск по полям, trace_id для связи записей одной операции, хранение с ротацией | `trace_id`, команда `trace`, «самые долгие операции», `purge_logs()` для удаления старых данных |

## Чем мы отличаемся

- **Локальная утилита, а не сервер.** Не нужно ставить агенты и держать кластер: достаточно `docker compose up -d` и загрузить принесённые файлы. Серверные системы (Loki, ELK) решают другую задачу — постоянный сбор с многих машин.
- **Хранение в SQL-базе.** В отличие от lnav и journalctl, данные остаются в PostgreSQL. Можно загрузить логи с нескольких машин, сравнить их и написать свой SQL-запрос.
- **Явные уровни и защита от дублей.** Уровень не угадывается, нестандартные уровни сохраняются, повторный импорт не искажает статистику.

## Что можно добавить по мотивам аналогов

- `search --follow`, как `tail -f` и `journalctl -f`.
- Автоопределение формата строки по нескольким шаблонам, как в lnav.
- Экспорт статистики в JSON для построения графиков.
