# Замечания преподавателя и что сделано в 0.2

| № | Замечание | Что сделано | Где смотреть |
|---|---|---|---|
| 1 | Непонятно назначение программы: всё в одном приложении | Архитектуру оставили, это согласовано. Назначение описано в README и `--help`: локальная утилита для загрузки, хранения, поиска и анализа принесённых логов | `README.md`, `logparser --help` |
| 2 | Сложно запустить: нужен установленный PostgreSQL | `docker compose up -d` поднимает PostgreSQL, схема создаётся автоматически. Сама утилита тоже работает в контейнере (`./lp`, `lp.cmd`), поэтому кроме Docker ничего ставить не нужно. В README пошагово описано всё, от запуска до остановки | `docker-compose.yml`, `Dockerfile`, `README.md` |
| 3 | Как программа понимает, к какому серверу подключаться (`conninfo = NULL`) | libpq читает `PGHOST/PGPORT/PGDATABASE/PGUSER/PGPASSWORD` или строку `-d "host=… port=…"`. Это описано в README, есть `.env.example`. `init` и `clear` выводят, к какому серверу подключились | `README.md#настройки-подключения`, `.env.example` |
| 4 | Справочник severity не пропустит FATAL; нельзя подменять уровень на `unknown` | Справочник удалён. Уровень хранится текстом как есть (`fatal`, `trace`, `audit`), в нижнем регистре. Числовой код 0..7 задан только для известных уровней. При импорте нестандартный уровень сохраняется, а утилита предупреждает о нём и называет его | `sql/schema.sql`, `src/parser.c`, `docs/database.md` |
| 5 | Угадывание severity по словам в сообщении | Удалено вместе с полем `sev_inferred`. Уровень берётся только из явной разметки (`<PRI>`, `[ERROR]`, `FATAL:`, `level=`). Если её нет, уровень `NULL` («-»), а импорт сообщает, сколько таких строк | `src/parser.c`, тест `test_no_guessing_by_words` |
| 6 | Повторный импорт создаёт дубликаты | Уникальный индекс `log_entries_uniq`, COPY во временную таблицу, затем `INSERT … ON CONFLICT DO NOTHING`. Импорт показывает, сколько дублей пропущено | `sql/schema.sql`, `src/db.c` |
| 7 | В `sources` лишние поля (`inode`, `last_offset`, `lines_total`), `path` UNIQUE, неясные `imported_at`/`uploaded_at` | Теперь `sources` — история **попыток**: `path` не уникален, `attempt` — номер попытки, `started_at`/`finished_at`, `status`, счётчики, `error`. Поля `inode`, `last_offset`, `lines_total`, `updated_at` и `log_entries.imported_at` удалены. Неудачная попытка тоже сохраняется. Команда: `sources` | `sql/schema.sql`, `docs/database.md` |
| 8 | `parse_errors`, `line_no`, NULL на ER-диаграмме | `parse_errors` оставили. `line_no` есть только там (в `log_entries` его нет и не было). На ER-диаграмме у каждого поля отмечено NULL/NOT NULL и когда бывает NULL | `docs/database.md` |
| 9 | Нет trace_id | Парсер извлекает `trace_id=` (а также `traceId=`, `trace-id=`, `trace=`), в БД есть колонка и индекс. Новые возможности: `trace <id>` (цепочка записей со смещением и длительностью), `search -t`, «самые долгие операции» в `stats` | `src/parser.c`, `src/db.c`, `samples/app.log` |
| 10 | Сверить с исходным ТЗ | **Нужно сделать вместе: нужен текст ТЗ.** Сейчас есть: топ-N программ и хостов по ошибкам, топ-N долгих операций, распределение по уровням, активность по часам, фильтры по уровню, программе, хосту, trace, периоду и тексту, CSV | — |
| 11 | Нет очистки базы | `clear` с подтверждением `[y/N]` (флаг `-y` пропускает подтверждение) выполняет `TRUNCATE` данных. Структура БД остаётся, сервер не трогается | `src/main.c` |
| 12 | Посмотреть аналоги | Краткое сравнение | `docs/analogs.md` |
| 13 | Цвета — не задача БД; уровни в одном регистре | Цвета есть только в `ui.c`. Уровень в БД всегда в нижнем регистре, это гарантирует `CHECK (level = lower(level))`. Синонимы `ERR`/`Warn` приводятся к `error`/`warning` | `src/ui.c`, `sql/schema.sql` |

## Как проверить

```bash
docker compose up -d
./lp import samples/sample.log samples/app.log
./lp import samples/sample.log          # «новых 0, дубликатов пропущено 19»
./lp sources                            # две попытки одного файла
./lp search -L fatal                    # нестандартный уровень сохранён как есть
./lp search -L -                        # записи без уровня — не угаданы
./lp trace a1b2c3                       # операция: 5 записей, 3 секунды
./lp stats                              # топ-5 и самые долгие операции
./lp clear
```
